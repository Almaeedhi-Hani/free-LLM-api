# Telegram phases 3, 4 and 5 — combined release
- Advanced features require TELEGRAM_OPS_ADVANCED_ENABLED=true after migrations, tests and live deployment. Existing owner webhook authorization remains the entry gate. No changes to GEO, schedule, publication thresholds, or AI quotas.
- Strategic memory: /remember text (explicit owner decision, 1000 characters), /memory (latest 5), /forget UUID (archive, not physical deletion). Memory is displayed alongside advice, never automatically executed. Source is the owner's Telegram message, not independent evidence. Do not store secrets; detector is best-effort.
- Reviews: /reviewlist (first 10 pending), /review fingerprint, /approve or /reject fingerprint, /confirm code. 10-minute expiration, exact full item fingerprint and content version, single atomic claim, audit and readback. Existing versioned admin content API enforces the original gates. Only explicitly low-risk, quality-eligible FAQ approvals may be attempted here; editorial approval, higher-risk FAQ, large items or duplicate questions require dashboard human review. Rejection supported for short FAQ and editorial. No bulk approval, no edits, no bypass of required official evidence. Uncertain writes are never automatically retried. Review rejected/blocked/uncertain intent states.
- Voice: separate TELEGRAM_OPS_VOICE_ENABLED=true and TELEGRAM_VOICE_GROQ_KEY secret, only after owner approves sending recordings to Groq and verifies free account limits. whisper-large-v3-turbo via official transcription API. One attempt per UTC hour, max 30 seconds and 1 MiB, no automatic retries, no audio/transcript persistence by this application (provider policies apply). Fixed Telegram/Groq endpoints. Voice can suggest only an exact read-only command; owner must type or tap it, no mutation from transcript. No voice synthesis. Provider may have its own billing/retention rules; not guaranteed free.
- Acceptance: unit checks, Next.js production build, review SQL grants, verify live deployment and RLS, test owner memory with a disposable note, archive note, review real item without publishing until explicit user confirmation, verify audit records, voice test after consent and key configured.
